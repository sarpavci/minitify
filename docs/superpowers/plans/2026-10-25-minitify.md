# minitify Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a minimal terminal controller for Spotify whose audio comes from a dock-invisible WKWebView player running the official Web Playback SDK.

**Architecture:** A Node daemon owns everything: it serves the SDK page over `127.0.0.1` (required for EME's secure context), holds the OAuth tokens, calls the Spotify Web API, and spawns a small Swift WKWebView process that registers as a Spotify Connect device and bridges macOS media keys. The CLI is a thin client that connects to the daemon over a unix socket, does one thing, and exits — so closing the terminal never stops the music.

**Tech Stack:** Node 24 (built-in modules only: `node:test`, `fetch`, `readline`, `net`, `http`), Swift via `swiftc` (WebKit + MediaPlayer frameworks), no runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-25-minitify-design.md`

## Global Constraints

- **Zero runtime dependencies.** Node built-ins only. No `package.json` dependencies, no `node_modules`.
- **Node 24+**, already verified on this machine (`node:test`, global `fetch`, `readline.emitKeypressEvents` all present).
- **Swift builds with `swiftc`**, Xcode not required. Build script lives in `player/build.sh`.
- **All commands and all user-facing text in English.** Code comments in English.
- **macOS only.** WKWebView and MPRemoteCommandCenter are platform-specific.
- Config at `~/.config/minitify/config.json`, tokens at `~/.config/minitify/tokens.json` with mode `0600`, daemon socket at `~/.config/minitify/daemon.sock`.
- Spotify search returns **at most 10 results** (API limit since February 2026). Show the 10 and tell the user to narrow the query; never paginate.
- Player page must be served over `http://127.0.0.1:<port>/player`. `loadHTMLString` does not work — its `about:blank` origin is not a secure context, so EME is unavailable.
- `WKWebViewConfiguration.mediaTypesRequiringUserActionForPlayback` must be `[]` or the SDK cannot start audio.

## Review Focus

These are the failure modes the spec implies but does not call out. Each one has a test in the task that owns the code.

1. **Corrupt or truncated `tokens.json`** — a half-written file must not crash the daemon on startup; treat it as "not logged in". (Task 1)
2. **Stale daemon socket** — a socket file left behind by a crashed daemon must not make every command fail forever; the CLI must detect `ECONNREFUSED`, remove it, and start fresh. (Task 7)
3. **Empty playlist or empty search result** — the selector must print a clear message and exit, not render an empty box or crash on index `-1`. (Task 8)
4. **Volume outside 0–100** — `minitify vol 150` must be rejected with a usable message rather than sent to the API. (Task 3)
5. **Track and playlist names wider than the terminal** — long names must be truncated to the terminal width so the list never wraps and corrupts the redraw. (Task 8)

### Task 5: Swift player with media keys

**Files:**
- Create: `player/wkplayer.swift`, `player/build.sh`
- Modify: `.gitignore` (already ignores `player/wkplayer`)

**Interfaces:**
- Produces: a binary taking the page URL as `argv[1]`. It writes one JSON object per line to stdout: `{"type":"loaded"}`, `{"type":"mediakey","command":"play"|"pause"|"toggle"|"next"|"previous"}`, `{"type":"error","message":"..."}`. It reads one JSON object per line from stdin: `{"type":"nowplaying","title":...,"artist":...,"durationMs":...,"positionMs":...,"playing":bool}`.

No unit tests — this cannot be exercised without a real display, DRM and audio device. It is verified manually in Task 9.

- [ ] **Step 1: Write `player/wkplayer.swift`**

An `NSApplication` with `setActivationPolicy(.accessory)` so no dock icon appears. A `WKWebView` in an `NSWindow` positioned at `(-5000, -5000)` and kept hidden with `orderOut(nil)`. `WKWebViewConfiguration.mediaTypesRequiringUserActionForPlayback = []`.

Media keys come from `MPRemoteCommandCenter.shared()`: add handlers to `playCommand`, `pauseCommand`, `togglePlayPauseCommand`, `nextTrackCommand` and `previousTrackCommand`, each printing its line to stdout and returning `.success`. A background thread reads stdin lines and updates `MPNowPlayingInfoCenter.default().nowPlayingInfo` with `MPMediaItemPropertyTitle`, `MPMediaItemPropertyArtist`, `MPMediaItemPropertyPlaybackDuration`, `MPNowPlayingInfoPropertyElapsedPlaybackTime` and `MPNowPlayingInfoPropertyPlaybackRate`, and sets `playbackState`.

Flush stdout after every write (`FileHandle.standardOutput` plus an explicit newline) so the daemon sees lines immediately.

- [ ] **Step 2: Write `player/build.sh`**

```bash
#!/bin/sh
set -e
exec swiftc -O "$(dirname "$0")/wkplayer.swift" -o "$(dirname "$0")/wkplayer"
```

### Task 6: Daemon

**Files:**
- Create: `src/daemon/index.js`, `src/player/control.js`
- Test: `test/daemon.test.js`

**Interfaces:**
- Consumes: Tasks 1–5.
- Produces: `startDaemon(): Promise<void>` listening on the socket from `src/config.js`, and `handleCommand(cmd, deps): Promise<Result>` where `cmd` is `{name, args}` and `Result` is `{ok: true, data}` or `{ok: false, error}`. `control.js` produces `createPlayer({pagePort, onMediaKey}): {start(), waitReady(timeoutMs), deviceId, stop(), sendNowPlaying(info)}`.

`handleCommand` supports exactly these names: `playlists`, `search`, `status`, `play` (takes a uri), `pause`, `resume`, `next`, `prev`, `vol`, `quit`. Anything else returns `ok: false`.

The daemon speaks newline-delimited JSON over the socket: one request object in, one response object out, then the connection closes.

**SDK errors reach the user through the next command.** The daemon keeps the last `error` event from the page in memory. When a command fails because the player is not usable, that stored message is returned instead of a generic timeout — so a non-Premium account reports Spotify's own `account_error` text rather than "player not ready". `sendNowPlaying` is called on every `state` event so Control Center stays current.
